# agent-deck の位置づけ — 素の Copilot との違い

「この機能は素の Copilot CLI / VS Code チャットでもできるのでは?」に答える文書。
導入判断や、チームへの説明にそのまま使える。事実関係は 2026-08-12 時点の一次情報調査
([sdk-notes.md](sdk-notes.md))に基づく。

## 大前提

agent-deck は AI エンジンを一切持たない。エージェント実行・サブエージェント委任・
ツール実行はすべて Copilot(公式 SDK 経由)がやっている。
**AI の賢さは素の Copilot と完全に同一**であり、このアプリの価値は「運用の器」の部分にある。

## 素の Copilot CLI / VS Code チャットでできること

| 機能 | 素の Copilot での実現方法 |
|---|---|
| エージェント定義(`.agent.md`) | CLI ネイティブ対応。`copilot --agent=<name> --prompt "..."`、対話中は `/agent` |
| 定義のチーム共有 | **組織スコープが標準機能**(組織の `.github` / `.github-private` リポジトリの `/agents`)。agent-deck の共有フォルダ同期は「組織管理者の設定なしで済ませる」ための代替 |
| モデル指定 | `--model` フラグ / 定義の `model` フィールド / `/model` コマンド |
| ツールの許可・拒否 | `--allow-tool` / `--deny-tool` フラグ(agent-deck はこの記法をそのまま採用している) |
| サブエージェント委任 | ランタイム標準機能(定義の name/description による自動委任) |
| 進行状況の表示 | ターミナルに逐次表示される(構造化・保存はされない) |
| 並行実行 | CLI を複数起動するだけ |
| 定期実行 | Windows タスクスケジューラ + `copilot -p ...` のスクリプトで代替可能 |
| GUI での対話 | VS Code チャット(カスタムエージェント・承認 UI あり。ただし開発者向けツール) |

## agent-deck 固有の価値

1. **出力フォルダ限定の自動承認ポリシー**
   「outputDir 配下の書き込みだけ無承認、外は必ず確認」は CLI フラグでは表現できない
   (`write(フィルタ)` はワイルドカード非対応 — ワイルドカードは shell 専用、公式ドキュメントで確認済み)。
   agent-deck は正規化済み絶対パスで判定し、`..` やシンボリックリンクでの脱出も防ぐ
2. **非エンジニアが安全に使える器**(初期仕様の核心要件)
   設定は一度ファイルに固めて全実行に自動適用。素の CLI では毎回フラグを正しく組み立てる
   必要があり、間違えるとガードレールが消える。ターミナル自体が二次利用者には障壁
3. **構造化された履歴・監査・来歴**
   実行ごとの成否 / 所要 / トークン / 生成ファイル一覧、「⚠ 出力は未完成の可能性」表示、
   セッション単位の監査ログ(全ツール実行と全権限判定)、成果物と定義バージョン・モデルの紐づけ。
   「この数字はいつ・誰が・どの定義で作ったか」に答えられる
4. **定期実行の統合**
   予約管理 GUI、実行キュー、無人実行時の「未承認操作は即失敗として記録」ポリシー、完了トースト。
   タスクスケジューラでの代替は可能だが、同等品はスクリプト群の自作になる
5. **複数セッションの俯瞰**
   ダッシュボード(実行中・待機承認・キュー・直近失敗)とセッション別ツリー表示
6. **管理者ガードレール**
   policy.json による強制拒否ツール(利用者側で解除不可)

## 使い分けの指針

- **エンジニアが一人でターミナルで使う** → 素の CLI + 少しのスクリプトでほぼ足りる。agent-deck はオーバーキル
- **非エンジニアを含むチームで定型業務を回す / 業務データの監査性が必要** → agent-deck の領分。
  上記 1〜3 が効く
- **VS Code を常用する開発者の対話利用** → VS Code チャットで十分

## 陳腐化リスクと見直し方針

Copilot CLI / VS Code の進化は非常に速い。「フォルダ単位の承認ポリシー」「実行履歴 UI」等が
本体に取り込まれた時点で、対応する自前実装の価値は薄まる。

**方針: Copilot 側のリリースノートを定期的に確認し、本体に吸収された機能は自前実装を捨てて
Copilot に委ねる(身軽さを保つ)。** 確認は `doc-researcher` エージェントで行い、
結果はこの文書と [sdk-notes.md](sdk-notes.md) を更新する。
